Code Diagrams:

This image shows my first assignment while working on Habit of Force. I was tasked with familiarizing myself with the code base and decided to create a figma board that documented the flow of all of the main mechanics in the game. Originally, I was going to create the diagrams only for the parts of the game I knew I was working on; however, as I continued to work on these diagarms, I was allocated two more new hires to expand the diagrams to every system in the game. This diagram ended up being incredibly helpful as we had four new engineers join development that summer, and it was able to orient them with the codebase without having to pull anyone on the project away from their work.
This image shows a part of the diagram mapping the enemy movement scripts in the game. This graph shows what the code was like before my movement system, in which the enemies would find the nearest player unit and move as close to them as possible. This particular snippet shows where the VFX for the movement system is executed.
This image shows the beginning of the script labeled "DumbEnemyManager". This script was responsible for both the movement and attacking logic of the enemies in the game. It was this script in particular that I spent most of my time with as this was where I connected my movement and attack system.

Unity Script:

This image shows what the final product of my AI script looked like in the Unity Editor. This script had two main sections. One for attack and one for movement. The main purpsoe of the attack section was to allow the designer to customize which target the enemy AI should attack in a given situation. For example, if you wanted the AI to be a "sniper" character, you would set the attack curve to a high value. The main purpose of the movement section was very similar to the attack section. Say you wanted to have a character that specialized in close quarters combat, you could set the path distance and target range curves to prioritize closer distances and have your enemy maintain that range.
Here is an example of a curve that is weighted for values in the middle range, with a preference for larger values if middle values could not be accessed.
